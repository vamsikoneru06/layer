# Layer — Decisions Log

Running log of decisions made during brainstorming. The full PRD/spec will live in
`docs/superpowers/specs/` once every design section is approved.

| # | Date | Decision | Why |
|---|------|----------|-----|
| 1 | 2026-09-24 | **Purpose:** portfolio project for product-company interviews; solo; no hardware. | Needs a live demo and an architecture that holds up to interviewer scrutiny. |
| 2 | 2026-09-24 | **Product:** template-first photo design editor (Canva / Instagram-post style). Users pick a template, drop their photos into frames, edit, export. | Chosen from the full-stack/heavy-frontend idea list. |
| 3 | 2026-09-24 | **No video / MP4.** Static designs only; PNG export. | Motion would double the data model and renderer; templates + photos is the core. |
| 4 | 2026-09-24 | **Template sources — all three:** seed JSON templates, in-app Author Mode, user publish-to-gallery. | They layer: JSON is the format, Author Mode creates it, Publish shares it. |
| 5 | 2026-09-24 | **15 pages:** Landing, Gallery, Template Detail, Shared View, Creator Profile, Sign in, Onboarding, Settings, Dashboard, My Designs, Media Library, Editor, Author Mode, Publish Flow, Moderation. | Heavy-frontend full app, built in 3 phases. |
| 6 | 2026-09-24 | **Guest-first:** edit + export without an account; account needed to cloud-save and publish. | Zero-friction demo for recruiters. |
| 7 | 2026-09-24 | **Phasing:** P1 working product (Editor, Gallery, Template Detail, Dashboard, My Designs) → P2 creator side (Author Mode, Media Library, Auth, Onboarding, Settings) → P3 community (Publish, Profile, Shared View, Moderation, Landing). | Each phase ends demo-able. |
| 8 | 2026-09-24 | **Rendering: Approach A** — own scene graph; Canvas2D compositor; own WebGL2 shaders for photo filters; DOM overlay for live text editing. | Canvas2D excels at text + clipping; renderer-agnostic scene graph allows full WebGL later. |
| 9 | 2026-09-24 | **From-scratch line (A):** engine + UI components + template format built from scratch. React/Next.js, Postgres + Prisma, Auth.js, S3-compatible storage, Google Fonts used as foundations. | Effort where interviewers dig; no hand-rolled auth/security. |
| 10 | 2026-09-24 | **Architecture (Section 1, accepted):** pnpm monorepo — `apps/web`, `packages/engine` (zero-dep, React-free), `packages/ui`, `packages/schema`. Commands in / state out. Vercel + Neon + Cloudflare R2. Vitest + Playwright + visual regression. | Engine testable in Node; one engine powers Editor, Author Mode, landing demo, export. |
| 11 | 2026-09-24 | **Document format (Section 2, approved):** flat normalized `nodes` map + `root` z-order; node types `frame` / `text` / `shape` / `sticker` / `group`; every photo lives in a frame; filters stored as parameters (non-destructive); `lock: free / content-only / locked`; `placeholder` frames; `schemaVersion` + migration chain; same validator on client and server. v1 cuts: single style per text layer, single page per design. | One code path for photos; lock levels keep template layouts intact; cuts keep text layout tractable. |
| 12 | 2026-09-24 | **Editor engine (Section 3, approved):** modules math / scene / commands (transactions coalesce drags into one undo step, 200-step history) / interaction state machine / hit-test (inverse world matrix + exact shape) / snapping (sorted guide lines + binary search, 6 screen-px threshold) / text layout (greedy wrap, shrink-to-fit via binary search, DOM overlay for typing) / render (Canvas2D, scene + overlay canvases, dirty flags) / filters (WebGL2 uber-shader + separable blur, preview-res while editing, full-res on export, cached, context-loss recovery, no-WebGL2 fallback) / export (1x–3x, 8192 px cap). No spatial index (<150 nodes, linear hit-test <1 ms). | Measured simplicity over speculative structures; every hard part is hand-built and explainable. |
| 13 | 2026-09-24 | **Template system (Section 4, accepted by proceeding):** Author Mode with engine-level lock policy (soft locks, user can unlock); templates copied on use; photo drop/swap/fill-in-reading-order; 20 seed templates; publish with privacy scrub + PII warnings + asset ownership checks; live-on-publish with report-based moderation and audit log. | Product-grade template workflow with security built in. |
| 14 | 2026-09-24 | **Author instruction to proceed:** build backend + security + CI/CD now; sections 5–7 decided in the spec and open for review. Stack changes: Next.js 16, Better Auth (instead of Auth.js), Drizzle + PGlite tests (instead of Prisma), asset IDs only in documents (no URLs). | See spec §14. |
| 15 | 2026-09-25 | **One rate limiter.** The Postgres fixed-window limiter (`rate_limits`) also backs Better Auth through `rateLimit.customStorage.consume`; Better Auth's own `rateLimit` table is not created. | One atomic upsert serves the API and auth routes; one table to clean up. |
| 16 | 2026-09-25 | **Client IP only from a trusted proxy.** Route handlers can't see the socket address (spec §9.6 said "socket address"). Without `TRUST_PROXY=true` all clients share one `unknown` IP bucket (fail closed), so production refuses to boot without it. Only a single-entry `X-Forwarded-For` is accepted (same rule as Better Auth). | Never key limits on a spoofable header. |
| 17 | 2026-09-25 | **CSP:** scripts are `'nonce-…' 'strict-dynamic'`; `style-src` allows `'unsafe-inline'` for Next/Tailwind inline styles. | Script injection is the XSS risk that matters; style nonces break framework-inserted styles. |
| 18 | 2026-09-25 | **Admin endpoints answer 403 to non-admins;** owner-scoped resources answer 404 to non-owners. | The admin API's existence is public; a resource's existence is not. |
| 19 | 2026-09-25 | **Design title mirrors `doc.meta.title`;** renaming rewrites both and bumps `version`, so an open editor gets 409 → conflict dialog. | One source of truth, no silent overwrite of a rename by a stale autosave. |
| 20 | 2026-09-25 | **Magic-link POST also passes our strict Origin check,** in addition to Better Auth's own checks. | Stops other sites from triggering sign-in emails (email bombing, login CSRF). |
| 21 | 2026-09-25 | **Only the Better Auth routes Layer uses are exposed.** `update-user`, `delete-user`, password, email-change, provider-token and account-linking routes are disabled; profile writes and deletion go through `/api/me` (validated, audited). Magic-link limits and the `name` length check run in a `hooks.before` so rejected requests store nothing; auth POST bodies are capped at 8 KB. | Found in final review: those routes bypassed validation, the audit log and the storage-deletion queue. |
| 22 | 2026-09-25 | **Every page renders dynamically** (`await connection()` in the root layout). | A per-request CSP nonce can't be baked into prerendered HTML; with `'strict-dynamic'` the scripts would be blocked. |
